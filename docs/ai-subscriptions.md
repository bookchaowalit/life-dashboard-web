# ความคุ้มค่า AI subscription

เปิดเมนู **ความคุ้มค่า AI** (`/ai-subscriptions`) และเลือกเดือนที่ต้องการดู
รองรับชื่อบริการและผู้ให้บริการอิสระ ไม่มีรายชื่อเจ้าที่จำกัดไว้

1. เพิ่มสมาชิกพร้อมราคาที่คุณจ่ายต่อรอบ หรือเลือกจัดหมวดสมาชิกเดิมเป็น AI
2. บันทึกแต่ละงาน: วันที่ ผลงานที่ได้ ผลว่าใช้ได้/บางส่วน/ไม่ได้ใช้ และอ้างอิงงานได้
   ใส่เวลาที่คาดว่าจะใช้หากไม่มี AI เวลาใช้จริงรวมรอ และเวลาตรวจแก้แยกกัน
   ถ้าไม่ทราบเวลา ให้เว้นว่าง อย่าใส่ศูนย์แทนข้อมูลที่ไม่ทราบ
3. บันทึกการจ่ายจริงพร้อมหลักฐานอ้างอิง เช่น เลขใบเสร็จ และช่วงบริการที่ยอดนั้น
   ครอบคลุม รวมวันแรกและวันสุดท้าย ไม่ต้องเก็บเนื้อหาอีเมลหรือบทสนทนา
4. กำหนดมูลค่าเวลาโดยประมาณต่อชั่วโมงในสกุลเงินของสมาชิก แล้วเลือกยืนยันว่า
   บันทึกการใช้ของเดือนนั้นครบแล้วเมื่อคุณตรวจครบจริง รวมถึงกรณีไม่ได้ใช้เลย
5. ทบทวนข้อสรุป เหตุผล และวันต่ออายุ ก่อนตัดสินใจด้วยตนเอง

## อ่านผลอย่างไร

- งานที่เสร็จและใช้ได้: เวลาที่ประหยัดโดยประมาณ = เวลาเมื่อไม่มี AI − เวลาใช้จริง − เวลาตรวจแก้
- งานได้บางส่วนหรือไม่ได้ใช้: นับเวลาใช้จริงและตรวจแก้เป็นเวลาที่เสียไป ไม่อ้างว่า
  ประหยัดเวลาที่คาดว่าจะใช้ทั้งหมด จึงแสดงเวลาสุทธิติดลบได้
- มูลค่าเวลา = เวลาที่ประหยัดสุทธิ × ค่าต่อชั่วโมงที่คุณประเมิน ค่านี้เป็นค่าประมาณ
  ไม่ใช่รายได้ที่ได้รับ ไม่บวกรายได้ที่เกี่ยวข้องซ้ำเข้าไปในมูลค่าเวลา
- ราคาต่อเดือนจากแพ็กเกจเป็นประมาณการ ต้นทุนจากการจ่ายจริงเฉลี่ยตามวันบริการ
  เช่น จ่าย 365 USD ครอบคลุมปี 365 วัน เดือนกันยายน 30 วันใช้ต้นทุน 30 USD
  แม้ชำระเงินตั้งแต่เดือนมกราคม ยอดเงินออกในเดือนกับต้นทุนของเดือนจึงแสดงแยกกัน
- ผลตอบแทนจากต้นทุน = (มูลค่าเวลาประมาณ − ต้นทุน) ÷ ต้นทุน × 100
  ต้นทุนศูนย์ไม่แสดงเปอร์เซ็นต์ผลตอบแทน
- ข้อมูลครบและสิ้นงวดแล้ว: มูลค่าครอบคลุมต้นทุนเป็น `worth_it`; ต่ำกว่าต้นทุนเป็น
  `not_worth_it` ซึ่งเป็นสัญญาณให้ทบทวนแพ็กเกจและคุณค่าด้านอื่น ไม่ใช่คำสั่งยกเลิก
- เดือนที่ยังไม่สิ้นสุดเป็นผลเบื้องต้น ไม่มีคำแนะนำให้ยกเลิกจากข้อมูลระหว่างงวด
- ยอดจ่ายไม่ครอบคลุมงวด ช่วงบริการซ้อนกัน สกุลเงินต่างกัน ไม่ทราบเวลา/ค่าเวลา
  หรือยังไม่ยืนยันการบันทึกครบ จะไม่ออกข้อสรุปสุดท้าย ระบบไม่แปลงสกุลเงิน
- การเพิ่ม แก้ไข หรือลบบันทึกการใช้หลังยืนยัน ทำให้ต้องยืนยันใหม่
  ความครบถ้วนผูกกับเดือนและเวอร์ชันของบันทึก ไม่ใช่แค่จำนวนรายการ
- การยืนยันระหว่างงวดครอบคลุมถึงวันที่กดยืนยันเท่านั้น ต้องยืนยันใหม่หลังสิ้นเดือน
  ก่อนออกข้อสรุปสิ้นงวด หน้าเว็บที่ข้อมูลเก่าจะถูกปฏิเสธหากรายการเปลี่ยนไปแล้ว
- วันยกเลิกไม่ถือว่าได้เงินคืน ต้นทุนจากใบเสร็จยังจัดสรรตามช่วงบริการที่จ่ายจริง
  ส่วนประวัติแสดงทั้งรายการที่จ่ายในเดือนและรายการที่ครอบคลุมบริการในเดือน

ประวัติแสดงรายการปัจจุบันพร้อมเวอร์ชัน และแก้ไขเวลา/ยอดจ่ายที่บันทึกผิดได้
การแก้ไขใช้เวอร์ชันป้องกันการเขียนทับข้อมูลจากอีกหน้าต่าง เมื่อชนกันให้โหลดข้อมูลใหม่
การส่งซ้ำหลังเชื่อมต่อล้มเหลวใช้รหัสคำขอเดิมเพื่อไม่สร้างรายการซ้ำ

## การเชื่อมระบบและขอบเขต

ใช้ Subscriptions cell เดิมผ่าน `EMPIRE_SUBSCRIPTIONS_API` และ server-only
`EMPIRE_CELL_TOKEN` ทุกหน้าต้องผ่าน owner session; การบันทึกตรวจ Origin และ JSON
ก่อนส่งไป cell ซึ่งคง authorization, audit, idempotency และ workspace isolation
อ่านข้อมูลไม่ครบหรือบริการไม่พร้อมแสดง unavailable แทนการสรุปว่าไม่ได้ใช้

ต้องลง migration 0003 ของ finance-subscriptions-api และปรับสิทธิ์จาก cell spec
ก่อนเปิดหน้าใหม่บนระบบจริง โดยอนุญาต read/write ของ subscription-usage,
subscription-charge และทรัพยากรเดิมที่ใช้ ส่วนการ deploy ยึด release policy ของแต่ละ repo

Monthly review ใช้วันสุดท้ายของงวดเป็น review_date สำหรับรายการที่หน้าใหม่นี้สร้าง
บันทึก verdict เป็น snapshot ณ ครั้งที่กดบันทึก; หน้ารายงานคำนวณใหม่จากหลักฐานปัจจุบัน
ค่า time_saved_hours เดิมเก็บเวลาที่ประหยัดไม่ติดลบ ส่วน net_minutes ที่ติดลบได้
อยู่ใน evidence ของ review ค่าดั้งเดิมของการใช้เก็บใน subscription-usages

การบันทึกงานและการจ่ายเป็น manual ในรุ่นนี้ โควตา Claude/Codex เดิมยังอยู่ใน AI Usage
ไม่ได้นำ token หรือเปอร์เซ็นต์โควตามาแทนผลสำเร็จของงาน
